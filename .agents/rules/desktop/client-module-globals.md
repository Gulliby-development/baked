A desktop client module (`apps/desktop/src/renderer/`) loads in any order and without a `window`: it reads browser globals through a `typeof` guard or inside a function, and a mock route module imports `response` and the route types from `client/mock-response.ts`, never from `client/mock-routes.ts`, which imports every route module. The desktop tests share one module registry, so a module that needs one load order fails every later test once the run picks another order; `apps/desktop/tests/module-load-order.test.ts` loads each route module first and the bridge without a `window`. A renderer module imports nothing that reaches a node builtin, static or dynamic, through `src/core` either: Vite externalizes it and the screen fails in the mock preview, so a pure model that `src/core` shares with the renderer keeps its file reads in a module of their own (`src/core/intelligence/test-file-at.ts`), and `apps/desktop/tests/renderer-node-imports.test.ts` walks every renderer module's import graph (#2683).
