A layout a host tool gives the lines it writes into a project file (`place_rows`' indentation, #2618) comes first from the request's own text where it shows one (`SuppliedRows.indent`), then the file, then a per-language record (`ROW_INDENT` in `src/core/tools/place-rows.ts`, registered in `tests/language-parity.test.ts` with a golden per fixture), never from a fixed constant alone; a constant is the fallback only for a language whose row is `none(reason)`. Such a tool states its default in its description and the brief's note, shows the written line in its result, and accepts a correction of that layout in one call (`reindent`), so a wrong guess never costs a session. Which file line holds a prescribed row is decided only by `heldLines` in the same file, which gives a row the request prescribes more than once the next equal line after its earlier copies, never the first equal line, so a duplicate row is held only as often as the file holds it. The same holds for what ends a written line: a separator the request's own row already ends with (`,` or `;`) is layout, kept by default and replaced by the caller's `separator` or `lastSeparator`, never doubled (`SEPARATOR_DEFAULT`; a C statement row once came out as `...;,`).
