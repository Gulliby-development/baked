A packaging system the package contents check builds (`PACKAGE_CONTENTS` in `src/core/workflows/quality/package-contents.ts`, a `LanguageRecord` registered in `tests/language-parity.test.ts`) states its manifests and their packaging fields (what decides the files a built package holds), the build commands tried in order and the parser that lists the build's files; a language whose packaging is not built keeps its `none(reason)` row. A new tool, or a new manifest of one, adds its `packageContents` golden to the language's fixture under `tests/fixtures/languages/`, a row to `MANIFESTS` in `tests/workflow-package-contents.test.ts` with one packaging and one plain change, and a listing case on recorded tool output there. A missing tool or a failed build is an attempt in the record, never a finding (#1984). A build that prints its listing and still exits nonzero (`dart pub publish --dry-run` exits 65 on a warning) names those exit codes in `listedExits` instead of hiding the failure behind a wrapper (#1986).
