An acceptance-rows test framework (`rowTest.framework`) ships both modes in the same pull request: a file template (`TEMPLATES` in `src/core/workflows/acceptance-rows.ts`) and an inline block (`src/core/workflows/acceptance-rows-inline.ts`) that uses only the language's standard library and test framework, so a brief that fixes its test files or forbids new dependencies can still use the rows. `tests/language-parity.test.ts` fails when a framework lacks the inline block (#1763). The row replay of source tasks (#1617) reuses that inline block in a one-shot file named by `REPLAY_FILE` in `src/core/workflows/acceptance-rows-replay.ts`, so a new framework also adds its replay file there and a row in `tests/acceptance-rows-replay.test.ts` showing the project's written-tests command runs that file alone, and a harness the block calls by a name every file of the language shares (RSpec's top-level `acceptance_actual`) is captured when its file loads, so a second test file that defines it changes nothing (#2335). A JSON reader the test framework itself depends on is no new dependency (jsonlite, which testthat 3 imports, and dkjson, which busted requires, #2348); a language whose standard library has no JSON reader writes the rows as literals of the test in both modes (Java, Kotlin, Scala), whose string literal never spells a quote, a backslash or a line break as a unicode escape, which Java and Scala 2 read before lexing (#2410); change how rows are run or read in those two modules, not in the scheduler or the executor.
