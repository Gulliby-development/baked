A command a project installs is run through its entry point, never by adding the command's name to the executables: a new manifest kind or language gets a reader in `ENTRY_POINTS` (`src/core/verification/entry-points.ts`), whose launcher is a program the checks already start, an `entryPoints` golden in its `tests/fixtures/languages/` fixture, and a stack row in `WITH_ENTRY_POINT` for the "doc examples entry points" cell of `tests/gate-matrix.test.ts`. The documented-example runner, `run_repro` and `run_probe` resolve it the same way through `entryPointCommand`, so a fix to one of them is a fix to all three (#1821). A command the project's build writes at its root, which a reader runs by path (`./ratdec`, `escript ratdec` after `mix escript.build`), is an entry point marked `byPath`; only such an entry resolves a `./name` form (#2511). A document's input is written by the host, never by a shell: a block the prose names (`extractFixtures`, #1849) or a `printf`/`echo` redirect line (`redirectFixture`, #2693); a new shape gets a case in the "documented-example fixture gate" block of `tests/gate-matrix.test.ts`, and an example that reads one lists it in `inputs` so its repro carries the file.
