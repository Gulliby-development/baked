A toolchain whose gates (`src/core/workflows/gates.ts`) list a formatter and a linter as separate tools makes the formatter's output pass the linter's gate in the same pull request, since the host runs a formatter's fixer (the format-written check, `src/core/workflows/format-written.ts`) after the lint check passed, and a rule the two decide differently turns the lint check red on every later task's tree (#2948: styler indents a multi-line R `if` condition 2 past the `if`, lintr's default `indentation_linter` asks for 6, and R101 turntrim opened 16 lintr correctives). Where the tools disagree on a rule, the formatter owns it: the lint gate leaves that rule's findings out whenever the formatter can run (the lintr gate drops `indentation_linter` lints when styler is installed, `STYLER_OWNS_INDENTATION` in `src/core/workflows/r-tools.ts`), and the edit tools' lint command (`detectProfile` in `src/core/tools/project.ts`) keeps the same findings. The lint gate's command never names the formatter, or `FORMAT_COMMAND` in `check-policy.ts` reads it as a format check. Each such pair gets a cell that runs the linter's gate on a recorded sample of the formatter's output with the project's default config, skipped without the tool, as `tests/workflow-scenario-r-styler-lintr.test.ts` does for R. Pairs from one tool or one shared config (ruff, gofmt and go vet, cargo fmt and clippy, `dotnet format`, swift-format) need no cell; the others (Prettier or Biome and ESLint, Pint or PHP-CS-Fixer and PHPStan, StyLua and luacheck or selene, `dart format` and `dart analyze`, clang-format and clang-tidy, RuboCop's layout and lint cops, shfmt and ShellCheck, Invoke-Formatter and Invoke-ScriptAnalyzer, scalafmt and scalafix) get one when a bench round shows a disagreement.
