Every config file that decides what a linter, formatter or type checker enforces is a row of `CHECK_CONFIGS` (`src/core/workflows/quality/check-configs.ts`), one table for every supported language; auto-approval (`alwaysNeedsPerson`, `CONFIG_KINDS`, the scope check, the planner's advice) and the manifest field check read it and never name a tool config of their own (#2221). A new linter or type checker, or a new supported language, adds its config files there with the fields that tighten it (`on`, `off`, `added`, `removed`, `raised`, `lowered`) or reads it as text, or gives the language `none(reason)`; check settings a manifest holds go into `EMBEDDED` in the same file. `tests/language-parity.test.ts` fails on a language without its `checkConfigs` golden, and `tests/check-configs.test.ts` runs every row's example through the approval (unnamed, named, opted in, deleted, created). Approving more than before stays opt-in (`autoApproval.requestedCheckTightening`), and a newly protected config declines only through the `check-config-approval` stop reason (shadow until promoted).
