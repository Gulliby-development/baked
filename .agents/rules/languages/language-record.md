Code that branches on a language, file extension, manifest or toolchain takes its data from an exhaustive per-language record (`LanguageRecord` in `src/core/intelligence/language-records.ts`): a row for every supported language, or `none(reason)` where the language has no such thing. Register each record in `tests/language-parity.test.ts`, with a golden in every language's fixture under `tests/fixtures/languages/`. Adding a language to `SUPPORTED_LANGUAGES` means filling every record and adding its fixture; the compiler and the parity test list what is missing. A worktree, task copy or documented-example copy gets the project's installed dependency folders only through `linkDependencies` (`src/core/workflows/dependency-dirs.ts`), which reads `DEPENDENCY_DIRS`: a toolchain that installs into the project (Composer's `vendor`, a local Bundler path) adds its row there, never a private list at a link site, and the snapshot and the run's content commit leave those links out through the same record (#2330). Each folder of that record also has a `PROJECT_PATHS` entry (or `none(reason)`): which of its installed files name the project itself (Composer's `vendor/composer` autoloader, an editable install's `.pth`, an npm workspace link), so a worktree gets its own copy of those and links the rest; a link of the whole folder would run the main workspace's code (#2362). Such an entry is judged by running the language's check tools from a worktree (`vendor/bin/*` launchers that find files from their own real path), not only by whether each entry is a link or a copy; `mirror` hard-links a folder's packages when they do (#2401). A folder that holds an installed copy of the project itself (the project's own rock in `lua_modules`, its package in an renv or packrat library, its pinned package's files in `_opam`) names that copy in `omit`, found by the project's manifest name, so the worktree leaves it out (#2371). A language whose package resolution is a generated, ignored file holding machine paths (Dart's `.dart_tool/package_config.json`) states its offline resolve command in `DEPENDENCY_PREPARE` instead of a link (#2361); the checks that load those packages are listed in `PREPARE_READERS`, and a prepare command that leaves a run's worktree unresolved is recorded once as an environment finding (`linkRunDependencies`), with those checks of that worktree `inconclusive`/`environment_broken` instead of opening corrections (#2372), and a test tool that fails past a working-directory length states it in `WORKTREE_PATH_LIMITS`, with the platform it was measured on, which the doctor checks against a task worktree's depth and a run reads once before its first task as the `worktree_environment` shadow reason (#2454). A run's worktree directory is named only by `runWorktreeDir` in `src/core/workflows/worktree.ts` (the run id's first 8 hex digits, with a `RUN_ID` file that names the run), never by joining `.baked/worktrees` and a run id at a call site; code that maps such a directory back to its run reads `worktreeDirRun`, and a scratch copy's cleanup removes the directory through `releaseRunDir`. A toolchain found failing below a deep worktree adds its row to `WORKTREE_PATH_LIMITS` and a case to `tests/workflow-scenario-worktree-path.test.ts`. The row's `tool` is the program and subcommand a check runs (`dart test`): the worktree preflight probe (`pathSensitiveChecks` in `src/core/workflows/worktree-probe.ts`, #2461) reads it to choose the required checks it measures, and `worktreeProbeDecision` alone decides from the two runs (failed in the worktree at the check baseline, passed in a short copy) whether `worktree_environment` comes from the probe; the row's length is only the fallback for a language with no measured check. `workflows.worktreeRoot` (#2461) moves run directories out of the project, and a worktree path is still stored relative to the project (`../../.bk/RUN/main`, refused by `worktreeRootProblem` on another drive or inside the project), so every reader joins `state.worktree.path` to the workspace and never assumes it starts with `.baked/worktrees`; a listing of run directories reads the configured root too (`worktreeUsage`), keeping only the directories whose `RUN_ID` names a run of the project.
