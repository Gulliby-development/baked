Skeleton content the host writes is a fixed point of the project's formatter: a formatter that reorders host-written lines (rustfmt's `mod` and `use` groups, gofmt's import blocks) gets a `SORTED_LISTS` row in `src/core/workflows/initiatives/skeleton-layout.ts` (a `LanguageRecord` registered in `tests/language-parity.test.ts`), and `layOutSkeletons` keeps the written order with whitespace only, so `layoutFree` checks and a spec's exact-content criterion still hold. A formatter that sorts across blank lines gets the row's `separator` (its own split marker, such as `# isort: split`) and `sorts`, which reads the project's configuration so a project that does not turn the sorting on gets no marker; one without a marker known to keep an order is a `none` row naming the tool (#2233). A new row, or a new formatter option that sorts, adds a fixed-point case to `tests/workflow-scenario-skeleton-formatter-order.test.ts` that runs the formatter when installed and a recorded order without it (#2222, #2233).
