A host tool that inserts into a file at a place the model names (`place_rows`) takes that place in a form an earlier insert of the same session cannot move: a line the model quotes (`after`, resolved by `anchorLine` in `src/core/tools/place-rows.ts`), with an absolute `line` only for a single call or to pick among equal lines, and its result names where the text went (the line it follows and the list that holds it, `placedWhere`), never only the line numbers, so a wrong place shows in the same turn. R102 tailcut `filters` T002 placed a two-list C++ file in two calls with lines computed before the first insert, and the second list's rows landed in the first (#2956); `tests/workflow-scenario-place-rows-two-lists.test.ts` holds that case. When the quoted text repeats (two lists that open with `return [`), the model names the n-th match from the top (`occurrence`), which an insert above it does not change, and a refusal lists the occurrences; R105 cutpick2 `bars` T003 spent 19 calls on such a PHP file with absolute lines (#2977, `tests/workflow-scenario-place-rows-nth-anchor.test.ts`). A file line that two prescribed rows could be (the request repeats a row's text) belongs to the row whose request neighbours are its file neighbours, never to the first copy by count, so a twin in another list is not taken for the row; R106 tokenpare `bars` T003 lost row 12 that way (#2980, `tests/workflow-scenario-place-rows-twin-rows.test.ts`).
