A test of a threshold comparison (`>` against a gap, a cap, a count limit) checks the value exactly at the threshold and one past it, on every input the comparison reads, and a test of a default setting asserts the default's value where the code reads it. A test that only uses values far from the threshold lets a `>` to `>=` mutant or a changed default survive the weekly hot-module mutation run (#3006: three `ExecutionClock` boundary mutants and `maxToolTimeouts: 3` survived that way).
