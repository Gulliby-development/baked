Every workflow that runs on `pull_request` or `merge_group` has a top-level `concurrency` group keyed by `github.event.pull_request.number || github.ref`, with `cancel-in-progress: true`. A newer push then cancels the superseded run and frees its runners. The account runs a limited number of jobs at once: on 2026-11-04 about 60 jobs ran side by side, and Linux jobs waited with no runner until the merge queue dequeued a pull request (#2915).
