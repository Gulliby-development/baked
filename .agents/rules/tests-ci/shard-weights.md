`OS tests` shards are balanced by each file's measured time in `scripts/test-shard-weights.json`, never by name. A change that adds a test file taking more than a minute on Windows or macOS, or moves time between files (a split, a merge), refreshes that table with `bun scripts/test-shard-weights.ts <windows|macos> <shard logs>...` in the same branch (see CONTRIBUTING.md); `tests/test-shard.test.ts` fails when a file would run in no shard or in two. A test file whose measured time on either OS passes about half a shard's 30-minute limit (15 minutes on a slow runner) is split by describe into files of its own, with shared helpers in `tests/helpers/`, and the table gets each part's time; the job's timeout is not raised (the replay corpus filled a macOS shard alone and passed 30 minutes, 2026-10-28).
