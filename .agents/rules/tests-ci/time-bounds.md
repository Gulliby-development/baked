A time bound inside a test never decides its outcome on a slow runner. A wait for things to happen at once (a rendezvous of parallel calls) waits for the number the code under test should reach, never more, and its bound only ends a run that never gets there (#1915). A bound inside a fixture (a child process's `timeout`, a worker call, a CLI call) stays a few seconds under the test's own limit, so the test's limit and its slow-test report, not a kill, decide a slow run (#1917, #1919).
