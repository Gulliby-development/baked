OpenTUI's process-wide tree-sitter client is taken only through `getTSClient` in `src/core/utils/syntax.ts`, which asks OpenTUI for the current client on every call and catches its start-up promise: destroying a renderer destroys the client, so a client kept in a module would be a dead one, and an uncaught start-up rejection fails the test run. A new OpenTUI singleton with a start-up or destroy promise follows the same rule, with a case in `tests/tui-syntax-style.test.tsx`.
