A vulnerable transitive dependency whose parent has not moved yet is fixed with an `overrides` entry in that lockfile's `package.json` (root or `apps/desktop`), only after checking that every caller still works with the new major (a CommonJS caller that calls `require("pkg")(...)` or a TypeScript `__importDefault(require("pkg")).default` breaks when the new major has no callable `module.exports` or `default` export). When only some callers can take the new major, scope the override to those parents (`"overrides": { "<parent>": { "<pkg>": "<range>" } }`, which Bun 1.4.3 honours) and leave the others on their own range, as `apps/desktop` does for minimatch; the pull request names the advisory, the callers left behind and the issue that removes the override once the parents catch up (#2518).
