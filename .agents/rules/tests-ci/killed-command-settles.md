`ProcessScope.execute` settles a command it killed within `KILL_EXIT_GRACE_MS` of the hard kill, with `timedOut` and `KILLED_NO_EXIT_NOTE`, even when the OS never reports the exit: five macOS queue runs ran a 10 s check into the 30 s test limit because the wait for `close` had no bound (#2858). A change to its kill path keeps that bound, and `tests/process-scope-kill-grace.test.ts`, which swallows the kill so the command outlives it, fails without it. A test that writes a stand-in tool and does not test how the tool is found runs it as `/bin/sh <script>` rather than exec'ing the fresh file, since macOS can hold the first exec of a new unsigned file on a policy scan.
