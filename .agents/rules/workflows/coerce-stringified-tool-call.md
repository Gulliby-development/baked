A tool argument a model sends as JSON text where the schema asks for another type is decoded in one place, `coerceStringifiedToolCall` in `src/core/agents/tool-input-coercion.ts`, run as the AI SDK's `repairToolCall` on every `generateText`/`ToolLoopAgent` call that offers tools; never in one provider adapter and never per field in a result schema (`z.preprocess`). A new model call that offers tools passes it. The types it decodes to are the rows of `COERCIBLE_TYPES`; a tool or `submit_result` schema field of a type outside that table (other than string or null) fails `tests/tool-input-coercion.test.ts` until the type gets a row. Text that does not parse to the field's type is left for the validator to refuse (#2141). Invalid and decoded tool inputs are counted per model only by `toolInputCounts` in `src/core/workflows/tool-input-health.ts` (the usage summary's `toolInputs`), and a recovery signal from them goes through `recordToolInputSignal`, which reads the ladder's `nextRung`, never a second ladder (#2149).
