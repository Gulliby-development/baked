A store write transaction never reads the process table (#2746): on Windows `processTreeAlive` runs PowerShell for seconds, and the SQLite write lock would block every other writer meanwhile. A transaction that reaches `commandProcessMayRun`, `commandMayBeRunning` or `releaseDeadOwnerLeases` (`src/core/workflows/leases.ts`), directly or through `checkRecoveryNote`, `noteInterruptedChecks` or `requestRecovery` (`src/core/workflows/recovery.ts`), first takes `using _liveness = commandLiveness(store, [runId])` for the runs it checks, so their verdicts are read before the lock. `tests/workflow-recovery-liveness-lock.test.ts` stubs the read (`processProbe.treeAlive`) and fails when it runs while the lock is held; a new such transaction adds its case there.
