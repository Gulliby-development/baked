An edit tool that takes a line number and a text to replace there reads the range from one helper (`oldStringRange` in `src/core/tools/line-range.ts`), never its own line count: a text that ends in a newline covers its lines and the line break after them, and `edit_file` and `multi_edit` must agree on it. A failed edit call is no edit for the progress watcher (`editedIn` in `progress-watch.ts`). R106 tokenpare filters T005 repeated one `edit_file` whose `oldString` ended in a newline 27 times, every call a mismatch the watcher counted as progress (#2981, `tests/workflow-scenario-edit-linestart-newline.test.ts`).
