A new way an implementer attempt can end unfinished (a cap, the watcher, a stall) reads the attempt's checkpoint before it blocks the task, as `hostFinishAfterStop` and `capEndResult` in `scheduler.ts` and the stall path of `NativeAgentExecutor.execute` do: `recordCheckpointWouldFinish` in `src/core/workflows/attempt-checkpoint.ts` records `decision.would_finish` (reason `attempt_green_checkpoint`, shadow) when the attempt's required checks failed on edits past a state on which they all passed. A new tool that runs a required check inside an attempt reports its run to the attempt's `CheckpointTracker` (#2470).
