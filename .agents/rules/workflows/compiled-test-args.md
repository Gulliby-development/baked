A written-tests or affected-tests run that selects tests by class (`dotnet test --filter`, maven's `-Dtest`, gradle's `--tests`; `compiledTestArgs` in `src/core/workflows/affected-tests.ts`) names the classes the file declares, read by `TEST_CLASSES` (`src/core/workflows/test-classes.ts`, a `LanguageRecord` registered in `tests/language-parity.test.ts` with a `testClasses` golden: a reader of the declared test types with their namespace or package, or `none(reason)` for a runner that selects by path), never the file's name; the name is only the fallback for a file that declares no type holding a test. A new class-filter runner joins `CLASS_RUNNERS` in that parity test, which fails for each language it takes without a `TEST_CLASSES` row, and a language whose test files such a runner takes adds its row with an `example` whose class is not named like the file (#2363). A class filter that exits 0 when it matches nothing (Maven's `-Dsurefire.failIfNoSpecifiedTests=false`, dotnet's `--filter`) must still read as zero tests run: a runner whose output may say nothing (`mvn -q`) gets its report counted by `testReport` (`src/core/verification/test-reports.ts`), and the gate matrix keeps a real-toolchain cell for a selection that matches no class (#2378).
