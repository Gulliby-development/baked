A shadow hook that runs before a task's implementer session goes through `beforeSession` in `src/core/workflows/scheduler.ts`, which both the single-writer path (`runTaskStep`) and the batch and candidate paths (`runTaskWorker`) call with the root the session edits; it is never added to one path's own pre-session steps. The hook adds its scenario case on both paths (one writer and `maxConcurrentWriters` 2, as `tests/workflow-scenario-host-apply-shadow.test.ts` and `tests/workflow-scenario-corrective-sliced-test.test.ts` do) and its name to the hook list in the host-apply shadow test, which fails when a hook is called outside `beforeSession` (#2138). The one exception is a task that runs no session: a host-written or host-applied task gets the supplied-content check (`recordSuppliedChecks`, #2275) in `runTaskStep` before the host writes its files, since no session follows (#2456); a corrective the host writes itself with the content its files already hold records `host_content_conflict` in `hostRewriteWouldStop`, called only from `repair`. A new check of host-written content goes through that same call, and its scenario case drives a host-written task, as `tests/workflow-scenario-host-written-check-conflict.test.ts` does.
