A run or task worktree is removed only in `removeRunWorktree` and `removeTaskWorktree` (`src/core/workflows/worktree.ts`), and both follow the same steps (#2806). First stop the holders under it. Then run `git worktree remove --force` as a best-effort `git()` call, never `required()`. Then `removeDirectory` with its lock retries, `moveAside` into `.baked/trash`, and `git worktree prune`. A failing git step never ends the removal: Git refuses a worktree it no longer lists (a moved project folder, a pruned entry) and a file a Windows process holds. A new removal path uses these helpers. Without them, the "a run worktree Git no longer lists is still discarded and cleaned (#2806)" case in `tests/workflow-worktree.test.ts` fails.
