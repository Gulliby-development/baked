A corrective's unowned file is parked on another initiative feature only when that feature is not a later one. Whether the feature depends on the run's own feature, directly or through others, is decided only by `laterFeature` in `src/core/workflows/corrective-scope.ts`, from `initiativeBounds`' `dependsOn`, and is recorded as `upstream.later` on the path (#2898). `unownedRule` refuses such a path with the remedies of a block, and never opens a `manual_evidence` request that only a later run could answer. A new request kind that waits on another feature's change asks the same question, with a case in the R96 varprompt block of `tests/workflow-scenario-corrective-unowned-file.test.ts`.
