A planned task names at least one file in `writes`, unless it is a verification task that names the checks closing it in `checkIds`, and a plan has at least one planned task that writes a file: `validateTaskGraph` (`src/core/workflows/schemas.ts`) refuses anything else, and the refusal goes back to the planner before approval (#3066). The host closes a planned task with no writes by its task checks without a session (`scheduler.ts`, `skipped: "no-writes"`), so an empty task the graph let through would be marked implemented with nothing written. A new plan-level invariant goes in `validateTaskGraph` with a case in `tests/workflow-scenario-empty-writes-plan.test.ts` or its own scenario, and a new host path that reads empty `writes` as "nothing to do" relies on this rule rather than checking again.
