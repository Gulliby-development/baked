A host write of prescribed rows (`rowFilePlan` in `src/core/workflows/row-file.ts`) takes each row's trailing `,` or `;` from the list's layout, never from the request row's own text: the rows before the last take the shape's row separator, and the last written row ends as the shape's last row does (no separator, a separator, or the list's close). A feature's slice of a shared row block ends with a row the request writes with its comma, because the block's later rows follow it there, yet in the slice's file it is the list's last row until a later feature's rows land. `tests/workflow-scenario-row-file-write.test.ts` (R107 netweave) fails when a slice's last row keeps the request's comma (#3000).
