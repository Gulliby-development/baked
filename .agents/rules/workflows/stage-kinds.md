A stage move in the scheduler (a replan, a return to specify, a revision after a rejection) finds its target with `stageKinds` and moves with `moveTo` in `src/core/workflows/scheduler.ts`, so it works for v1 and v2 definitions, and its caller marks a v2 move `rerouted`; no other code reads the run's definition with the v1 `WorkflowSchema` to find a stage, and a v2 run is never moved by setting `stageIndex`. A new move adds a v2 (quick) case to its scenario test, as `tests/workflow-scenario-v2-sizing-replan.test.ts` does for the sizing replan (#2036).
