The separator `place_rows` (`src/core/tools/place-rows.ts`) ends a placed row with, when neither the caller nor the row's own text gives one, comes from the row's shape before the language's `ROW_SEPARATOR`: `shapeSeparator` gives none to a command row (a name, a space and its first argument, a statement and not a list element) and to rows of a list that already holds the request's rows with no separator (#3069, R111 skillgate: PowerShell command rows in `$failures = @(` stopped parsing after the default comma). A language whose rows are constructors written like commands (OCaml, ReScript `Some x`) an expression opened by a keyword (`new Row(...)`, `EXPRESSION_WORDS`) or a struct literal (`Row { ... }`) keeps its language's separator; a new such case joins `shapeSeparator` with a case in the R111 describe block of `tests/place-rows.test.ts`.
