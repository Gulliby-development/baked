The host writes a prescribed-row file only when its shape holds one list of the rows' kind (`rowFilePlan` in `src/core/workflows/row-file.ts`). An empty list counts too: a line that opens a list as the run's own opening line does (names aside) and closes it on that line or the next (`emptyLists`). A run count alone never tells the host where a row goes, because an empty list holds no row line. With a second list the host declines, and the session places each list's rows with `place_rows` and `after`. A new row writer or shape reader that picks a list adds its two-list case, with one list still empty, to `tests/workflow-scenario-row-file-write.test.ts`. That file's R108 netknot and drawsieve scenario fails when the second list's rows land in the first (#3016). Which list a row belongs to comes from the request's division (#3019), never from the flat block order.
