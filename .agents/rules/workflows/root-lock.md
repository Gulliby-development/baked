A host tool that runs a project command inside an attempt (`request_check`, `apply_fix`, `run_probe`, and any new one) runs it inside `withRootLock(root, ...)` from `src/core/workflows/root-lock.ts`, so the parallel tool calls of one turn take turns in a task's directory instead of racing for its build directory (#3047). The lock is keyed by the resolved root alone, never by a per-toolchain table, and a new tool adds a same-turn case to `tests/workflow-check-fix.test.ts`.
