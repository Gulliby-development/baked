The test-task split rule is one rule in three places: the oversize decision (`exceedsTestCapacity` and `sizePlan` in `src/core/workflows/sizing.ts`), what the planner is told (`plannerSizing`, `splitNote`, `ROWS_TASK_NOTE`) and what the host can split (`splitTestTasks`, which skips rows tasks, and the rows rule in `rowPlanProblems`). A change to one updates the other two, so sizing never asks for a plan the host cannot make and the planner may not write, and adds a case to `tests/workflow-scenario-rows-task-sizing.test.ts`; a new rows framework adds its row there (#1930). Sizing prices a task by who writes it: a task the host writes with no session (`hostWritten`, or a row file under `rowFileWrite: "on"` through `hostRowFileTasks`, the scheduler's own `rowFileTasks`) costs nothing; ask the executor's decision, never a copy of it (#2633). The initiative estimate and its budget preview, priced before any plan, ask the same decision per file (`hostWritesRowFile`, through `hostRowFiles` and `hostRowCases`): a host-written row file is neither a path nor test cases there, and a new reader of who writes a row file goes through that one predicate (#2640). A change that takes paths or cases off a feature in the estimate moves its price only where something reads them (the path fit, `fewPathDetail`, the path or test floors); its pull request shows the moved ranges on the bench-trace corpus with `replayInitiativeStarts`, never on a synthetic pool alone (#2640). An opt-in sizing rule that moves a feature's price records on the feature's estimate whether it applied, why and the range before and after (as `fewPathShare` does with `FewPathShareRecord` in `few-path-record.ts`), and the split preview and the `feature.share_gate` record carry that record, so a bench round can count what the rule did (#2869).
