Hot harness modules ([`.github/hot-modules.json`](../../../.github/hot-modules.json): cost forecast, sizing, cap growth, auto-approval, provider timers, scheduler retry) follow an error budget ([docs/bench-loop.md](../../../docs/bench-loop.md#hot-modules)): at most one behavior change per hot module per bench round, and after a round with two or more stops caused by fresh fixes only reverts and regression fixes in those modules until a round passes without one. A pull request that changes one is labelled `hot-module` and runs the module's tests and the forecast replay on their own. A change to an attempt's caps or step floor (`AttemptStepController` in `src/core/workflows/step-budget.ts`) recomputes them on the recorded attempts in `tests/attempt-floor-backtest.test.ts` and says in its pull request how many attempts change and whether any loses room. A module that shows two escapes in a month (`bun scripts/hot-modules.ts escape`) is added to the list in the same pull request as its fix; a new file of a listed module's computation joins that module's `paths`.
