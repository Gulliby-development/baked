Whether a supplied task, a test task included, is split is decided by `suppliedTaskPrice` in `src/core/workflows/sizing.ts` on its supplied lines alone: `sizePlan` never applies the case capacity (`exceedsTestCapacity`) to a task with `basis: "supplied"`, and `splitTestTasks` never slices its files by criterion or by rows. The host split's report (`splitTests` in `scheduler.ts`) and the plan's report both read the request, so one task gets one basis before anything is cut, and `splitTestTasks` decides `basis: "supplied"` before any cut (#2594: a supplied new test file was sliced by its case price and every slice then priced from the same diff). A task kind the supplied rule leaves out states its reason in `suppliedTaskPrice`, with a case in the scenario test (#2019).
