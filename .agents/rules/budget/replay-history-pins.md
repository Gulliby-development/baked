A read of another project's workflow store (a policy's `sizing.historyStores`) goes through `historySnapshot` (`src/core/workflows/history-snapshot.ts`), keyed by the store's database path and a `kind` that names everything else the result depends on, so a replay pays for it once. The replay corpus pins each history trace it opens with `pinHistoryStore` to the trace file and the runs it has removed, and pins it again after every removal; a replay that changes a history store any other way pins the new content too, or its reads would return the old rows. Without the pins every start of every replay read every history trace again, and the corpus files outgrew a macOS `OS tests` shard (#3014).
