A `split` edit (`applySplitEdit` in `src/core/workflows/initiatives/plan.ts`) gives its parts every per-feature datum of the original that says what a feature owns, not only its texts and boundary: each skeleton file (`partSkeleton`) and each path's typed `rows` (`partRows`, read through `joinedRows`) go to the first part whose paths name the path, so each keeps one owner. A part left without them states no rows, and `featureRowSplit` gives the rows no sharer states to every silent sharer, so a split that drops a field moves ownership to other features with no record. A new field of `InitiativeFeatureSchema` that a feature owns per path gets its part rule in the `split` case and a case in `tests/workflow-scenario-split-keeps-rows.test.ts`, which fails when a split drops the original's rows (#2939 follow-up).
