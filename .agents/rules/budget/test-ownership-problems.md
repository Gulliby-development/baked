Which feature may own another feature's tests is decided only in `testOwnershipProblems` (`src/core/workflows/initiatives/plan.ts`), which the scheduler and the initiative service both call; a new rule about `testedBy` goes there with a case per supported language layout in `tests/initiative-plan-testedby.test.ts`, never as a second check elsewhere (#1873). That includes which feature may own a test file the request prescribes rows for: `rowOwnerProblems` reads the rows only through `suppliedRows` and joins each row with the literals a later feature's contract or scope quotes through the case walk's `literalCase` and `testsHold`, behind the `initiative-row-owner` reason (shadow, recorded on the initiative when the split is proposed; enforced, returned to the decomposer, #2487); a new ownership rule for tests, or a new source of a feature's literals (its approved spec's criteria), goes there with a case per supported language layout in the same test file.
