A planned-ahead initiative feature (`workflows.planAhead`, #1834) is held only by its run's `planAhead` state and the `hostRelease` requests the scheduler's task-graph stage creates; it is released only through `NativeWorkflowService.releaseBase`, called from `InitiativeService.releasePlanned` once every upstream feature is accepted, and its provisional base comes only from `featureBase` with the unfinished upstream features (`provisionalBase` in `src/core/workflows/worktree.ts`). Never start a feature's tasks on a provisional base or decide a `hostRelease` request anywhere else; `tests/workflow-initiatives.test.ts` "plan ahead (#1834)" covers the overlap, the release and a contract that changes under a planned-ahead feature. A fork of a worktree run publishes its documents again into its new worktree (`forkRun` clears `published`). A check of a plan against the workspace (a path that must exist) takes a planned-ahead run's upstream files into account only through `pathsExistLater` (`src/core/workflows/dependencies.ts`): until the release, the boundary paths of every upstream feature it pins, finished or not, readable but never writable, with cases in "plan ahead (#1834)" (#1932, #1946). A plan action the release makes stale (a planned `create` of a file the release brought in, which an accepted upstream feature wrote, or a planned `modify` of a file the provisional base tracked and the release removed, such as an upstream skeleton stub the accepted upstream deleted or renamed) is converted only at the release, by `releasedCreates`, `releasedModifies` and `applyReleasedCreates` (`src/core/workflows/dependencies.ts`) recorded as the `host-release` correction link that acceptance replays (`src/core/verification/acceptance.ts`: a new `modify` only of a file the released baseline holds, a new `create` only of one it lacks), never by loosening the tool policy's `Create target already exists` or `Modify target is missing` guard; a new kind of stale action joins `releasedCreatesBetween` and the link's `released` entries (each says the action it becomes), a new path that moves an approved run onto a new base converts its actions the same way, and the "plan ahead (#1834)" cases for R82 slotprompt and for the removed stub fail when it is skipped (#2514, #2517). The conversion lives only in `src/core/workflows/release-writes.ts` (`releasedCreatesBetween`, `staleReleasedCreates`, `recordReleasedCreates`) and is called at the release, at `resume` before the repeat guard, and at the task-graph stage of every drive of a released run, so a run released before the conversion is converted when it is picked up again; a new path that loads a released run and starts its tasks calls it, with a case like the resume case in "plan ahead (#1834)" (#2540).
