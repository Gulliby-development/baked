Which prescribed rows of a row file that several features share each one owns is decided only by `featureRowSplit` in `src/core/workflows/initiatives/plan.ts`. Its sources, in order: a feature's typed `rows`; otherwise its scope's words, read through `scopeRowRanges` in `src/core/workflows/feature-rows.ts`; otherwise the rows that no sharer names (#2898). `featurePrompt` states a feature's rows, and its upstream sharers' rows, under `FEATURE_ROWS_HEADING`, and `suppliedRows` keeps only those rows in the feature's run. Every reader of a task's prescribed rows (host write, row-file tasks and their price, restore, drift, `place_rows`, case walk) therefore sees the feature's rows through `suppliedRows`, and never re-reads the whole block or the scope. A new reader, or a new source of a feature's rows, adds its case to `tests/workflow-scenario-feature-row-ranges.test.ts`, which fails when a feature's run holds a row of another feature. A new row notation is covered there by its `ROW_FILE_SHAPES` example.
