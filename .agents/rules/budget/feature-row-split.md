Which prescribed rows of a row file that several features share each one owns is decided only by `featureRowSplit` in `src/core/workflows/initiatives/plan.ts`. Its sources, in order: a feature's typed `rows`; otherwise its scope's words, read through `scopeRowRanges` in `src/core/workflows/feature-rows.ts`; otherwise the rows that no sharer names (#2898). `featurePrompt` states a feature's rows, and its upstream sharers' rows, under `FEATURE_ROWS_HEADING`, and `suppliedRows` keeps only those rows in the feature's run. Every reader of a task's prescribed rows (host write, row-file tasks and their price, restore, drift, `place_rows`, case walk) therefore sees the feature's rows through `suppliedRows`, and never re-reads the whole block or the scope. A new reader, or a new source of a feature's rows, adds its case to `tests/workflow-scenario-feature-row-ranges.test.ts`, which fails when a feature's run holds a row of another feature. A new row notation is covered there by its `ROW_FILE_SHAPES` example. A feature's typed `rows` are read through `joinedRows`, the union of every entry for a path, never the first entry alone: the decomposer writes one entry per run of rows, and `mergeFeatures` carries the joined rows of every part (#2939). A merge reads the parts' rows from `featureRowSplit` of the plan before it (`mergedPartRows`, given the initiative's request by every caller of `mergeFeatures`), never from the typed entries alone: a typed entry hides the merged scope's words, so a part whose rows were words or the free rows would lose them. A new caller of `mergeFeatures` passes the request, and a new source of a feature's rows adds its merge case to `tests/workflow-scenario-merge-word-rows.test.ts`, which fails when a merge leaves a part's rows unowned.
