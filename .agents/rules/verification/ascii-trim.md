The case walk (`src/core/verification/criteria-cases.ts`) trims and splits a criterion literal only on ASCII spaces and tabs (`asciiTrim`, `[ \t]+`), never with `trim()` or `\s`, which also take a BOM, NBSP, U+2028, U+2029, U+3000 and a bare CR that belong to the literal; its quote scans (`QUOTED`, `DOUBLE_QUOTED`) match an empty span (`""`) so it never pairs with the next span's quote, and `literalCase` keeps an empty literal from becoming a case. `tests/workflow-scenario-case-walk-invisible-literals.test.ts` holds a cell per character and language spelling (#1979, #1980). Criteria whose rows the host wrote are not demanded from the test text: while the task's inline rows block is intact (`hostRows` in `CaseContext`, checked with `hasInlineRows`), the walk skips those criteria's table cells, and for every other case it decodes the test text to a canonical form (`canonicalLayers`) as it does the literal; a new inline framework or a new text shape adds a cell to the gate-matrix block "inline rows block holds its own cells" (#1997, #1846 family).
