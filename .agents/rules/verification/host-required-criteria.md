A criterion the host's own rules require (`HOST_REQUIRED_CRITERIA` in `src/core/workflows/host-required-criteria.ts`) states its condition once, as its `required` predicate; the scheduler's host-required filter, the `extra.crossPlatform` notes for the spec author and the spec reviewer, and the condition text the prompts read all derive from it, so analysis never demands a criterion the author is told not to write, nor objects to one it is told to write (#1765, #1831). `tests/workflow-scenario-analysis-cross-platform.test.ts` checks that the readers agree. An entry with one correct form (outcome, method and requirement fixed by the host's rule) also states how the host writes it (`written`), and the host adds it after specify instead of asking the author (`addHostRequiredCriteria`); a new such entry adds a case to `tests/workflow-scenario-host-cross-platform-criterion.test.ts`. A criterion that names a CI file is exempt from the host-bound repair only when it reads the file, not when it asks for what the CI jobs report (#1943). Every reader of that decision takes the request with its accepted answers through `statedRequest` (`src/core/workflows/stated-request.ts`; the scheduler's `criterionRequest`), never `state.requestText` alone, and a revised spec staged by `stageRevision` gets the specify-stage repairs; the #1964 cases of `tests/workflow-scenario-analysis-cross-platform.test.ts` fail when a reader or the revision path skips them. A criterion checked against content the request supplies verbatim is decided at analysis, on the host, like `hostFileSpecProblems`: `suppliedContentFindings` in `src/core/workflows/supplied-content.ts` runs the case walk on the supplied test files through `suppliedBlocks` (the one reader of verbatim blocks), and a new verbatim-content shape the reader takes adds a case to `tests/workflow-scenario-supplied-content-criteria.test.ts` (#2006). A `spec_conflict` about a supplied file that cites no criterion takes its criteria from the same walk (`suppliedConflictCriteria`), never from a reader of its own, so the request re-audit checks them at the first report.
