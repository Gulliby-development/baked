Every file the documented-example runner (`src/core/verification/doc-examples.ts`) writes into its copy of the workspace (a README fixture, a `printf`/`echo` redirect, any new write) goes through `writeIntoCopy`, which refuses a path that crosses a folder the copy links from the workspace and turns a file-system error into a `not_run` reason, never an exception of the review. Every folder the runner links into the copy (`linkInto`, `prepareExampleBuild` through an `EXAMPLE_BUILD` row's `link`, `linkBuildOutput` through `BUILD_DIRS`, an entry point's `link`) is in `LINKED_DIRS`, which `fixtureName` reads so a path under one is never a fixture; a new link registers its folder there and gets a row in `tests/workflow-scenario-doc-example-linked-build.test.ts`. R101 dieodds-update saved a README block as `src/Dieodds/bin/Release/net10.0/dieodds.exe` through the linked `bin`, and the recursive mkdir threw EEXIST on Windows and blocked the run with host_error (#2947).
