A repro's files and arguments reach the workspace's code only through the root it runs in: every executor of a repro goes through `runRepro`, whose `rerootRepro` (`src/core/verification/repro.ts`) replaces `{root}` and the absolute path of any other root of the run (a run worktree, the workspace) with that root. Another root is found through the run's `RunRoots` (`runRoots` in `src/core/workflows/worktree.ts`: the workspace and the run's worktree directory), never by the `.baked/worktrees` spelling alone, which a run under `workflows.worktreeRoot` lacks; the check baseline's signatures in `output-counts.ts` and its workspace-relative diagnostic paths (`relativeHeaded`) read the same (#2697, #2731), and code without the run's state (language servers, an edit's importers) finds a run worktree with `runWorktreeAt` in `src/core/verification/run-roots.ts`, never by matching `.baked/worktrees` alone. A new executor never runs a repro's files by itself, and a new language's way for a probe project to name local code (a path dependency, a replace, an include path) gets a row in `REFERENCES` of `tests/workflow-scenario-repro-root.test.ts` and in `PROBE_REFERENCE` of `tests/gate-matrix.test.ts` (#2279).
