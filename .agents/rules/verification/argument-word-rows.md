Whether a prescribed row holds a criterion's command-line literal is decided in `prescribedRowsHeld` (`src/core/verification/criteria-cases.ts`), which also reads the row as argument words through `rowTokens` (`src/core/workflows/row-block-drift.ts`), the one row token reader `row_block_drift` compares by, never a second one: the literal's ASCII-space words are consecutive tokens of one row, or follow a leading program name no row holds at the row's start (#3061). A new row notation that `rowTokens` reads, or a new spelling of a command line in criteria, adds a case to the `#3061` scenario in `tests/workflow-scenario-casewalk-prescribed-rows.test.ts`, with the negative case of a command line no row holds; a function the plan only names in its task descriptions (a code span or a snake_case word) is a helper (`plannedNames`), not a case.
