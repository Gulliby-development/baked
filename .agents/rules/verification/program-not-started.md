A check whose launcher starts but cannot find the program (cmd.exe's "is not recognized", a shell's exit 127, `bundle exec`, `uv run`, `poetry run`, `pipenv run`, `pdm run`) is a start failure, recognised only through `PROGRAM_NOT_STARTED_LINES` in `src/core/verification/program-not-started.ts`, which the check runner's `run` and `measure` both read: the result is `spawn_error`, and `failFastUnavailable` stops the run in the baseline as in the task and checks stages (#3040). A new environment runner in `ENVIRONMENT_RUNNERS` or a new launcher adds its line to the table (and the runner to `RUNNER_LINES`) with a case in `tests/workflow-check-unavailable.test.ts`, which fails for a runner without a row; a line must name the check's own program, so another command's output never matches.
