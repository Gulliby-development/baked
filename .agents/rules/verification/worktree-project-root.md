A command BAKED runs in a task's linked worktree (`.baked/worktrees/RUN/...`, inside the project's own checkout) must not find its project root in the main checkout above it. A build tool that walks up past the nearest root file, or reads one a project leaves out of git, gets that root from the worktree through `src/core/workflows/project-root.ts`, never through a flag at one call site. `withProjectRoot` adds dune's `--root` to every check command (`executeCheckCommand`). `withProjectRootEnv` gives checks and the session shell `DUNE_ROOT` and, when the worktree has no `go.work` of its own, `GOWORK=off`. A new tool with that walk adds its case there, as well as to its gates. `tests/workflow-scenario-worktree-project-root.test.ts` (R108) fails when a dune or go stand-in in a real `git worktree` takes the main checkout's root (#3011).
