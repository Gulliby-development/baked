A failed required check that the run's own plan cannot repair (static debt from before the run, a test check that collected no test in a plan that writes none) is exempted in one scheduler helper (`staticDebt`, `noOwnedTests`, `hostDocumentDebt` in `src/core/workflows/scheduler.ts`) that both check stages call (`runChecks` for v1, `runCheckStage` for v2), and records a `checks/<kind>/` artifact with the evidence id. Each exemption has a v2 (quick) case in its scenario test, since the v2 command-gate stage once skipped `staticDebt` (#1393). Acceptance and every view of a run's checks (report, view, compare, delivery) read that decision only through `hostPassedChecks` and `decidedChecks` (`src/core/verification/host-passed.ts`); a new exemption kind is added there, and a new reader of check results goes through `decidedChecks`. A test runner's "no test collected" output is added to `noTestsCollected` (`src/core/verification/convergence.ts`) with a cell in the gate matrix's "no tests collected (#1864)" block, for every supported language whose runner prints it. A runner whose "no tests" line one part of a run can print (a Go package's "[no test files]", an umbrella app's "There are no tests to run", a Gradle project's test task) also needs the line of a part that holds tests read by `heldTests` (`src/core/verification/output-counts.ts`), which overrules it, with a negative case in that block (#2778). A test target that exists and holds no test, which its runner reports with exit 0 and a summary of none (Swift's "Executed 0 tests", dotnet's "No test is available in"), is read only by `emptyTestRun` (`src/core/verification/output-counts.ts`): a counted runner whose zero summary means an empty target joins `EMPTY_SUMMARIES`, any other runner's line joins `EMPTY_RUN_LINES` with the line that says another part of the run held tests, each with a recorded or documented output in that matrix block and a negative case (tests that ran or failed, a narrowed selection, a test file that did not load); cargo's "0 passed" stays out (#2419). A test check that runs a test script with its interpreter has no runner output to read; its script is read instead by `emptyTestScript` (`src/core/verification/empty-test-script.ts`), and a language whose interpreter runs a test script directly adds its `SCRIPT_LANGUAGES` row (interpreters, extensions, the comments and inert lines that run no code) with a row in that block's plain-test-script cell (#2611). A formatter check that fails only on the documents the host publishes (#2641) is read only by `hostDocumentFailure` (`src/core/verification/host-documents.ts`): a new document the host writes into the workspace for a run joins `SPEC_PUBLICATION_FILES` (`src/core/specs/render.ts`), and a new whole-tree formatter or lint gate that reads Markdown or JSON adds its report reader to `FORMAT_FAILURE_READERS` with a cell in the gate matrix's "host-published documents in a formatter report" block, which fails when a reader has no cell.
