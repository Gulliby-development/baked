Whether the host writes one file of a planned task from the request is decided per write by `hostApplyWriteReason` in `src/core/workflows/host-apply.ts`, the per-write verdict that `hostApplyDecision` (the task verdict, first write's reason in write order) and `hostApplyPartialSplit` (#2937) both read; no other site decides a single write. A new host-written kind (another block form, a new row shape, a new decline reason) adds its verdict there and a case to the per-write table and the partial scenario of `tests/workflow-scenario-host-apply-partial.test.ts`, which fails when a reason is not a per-write verdict or the split writes a declined file. Under `hostApplyPartial: "on"` the host writes the split's `written` files only through `hostApplyContents` and `writeHostFiles`, each kind still under its own setting (`hostApply`, `rowFileWrite`), and the session of the task gets only the declined `session` files as writes, with the host's files as read hints; a new path that starts a session for such a task (a retry, a restart, a corrective's rerun of it, another worker) scopes it from the record's `partial` (`partialScope` in `scheduler.ts`), never from `task.writes`. The setting is documented next to `hostApply` and `rowFileWrite` in `docs/workflows/runtime.md`.
