Every run of a check's `fix` or `fixUnsafe` command goes through `runFixer` in `src/core/workflows/fixer-run.ts`, which returns the exit code and the output's tail; the caller reports both, never only the exit (#2436): `apply_fix` returns them per run in `fixed`, and the host pass `fixFiles` records `fixers/<check>/<attempt>.json` and `fixers/failed.json`, whose failed runs on a task's files reach its next attempt as the `failedFixers` attempt-context key. A fixer's command line is built only by `fixerCommand` or `wholeUnitFixerCommand` in `check-policy.ts`; a fixer whose command takes no file (an sbt task other than an `...Only` one, a Maven goal, Gradle's source-set tasks) runs once as configured (`takesNoFile`), and a new fixer form adds its row to the #2436 block of `tests/gate-matrix.test.ts`. `tests/workflow-scenario-fixer-failure.test.ts` scans for a fixer command run by any runner but `runFixer` and fails on it. Whether a fixer can run at all is probed once before the first task only by `probeFixers` in `scheduler.ts` (decided by `fixerProbeDecision`, the `fixer_unusable` shadow reason, #2442); a block's diagnostic lists the standing failed runs through `failedFixersBlockNote`, never its own reading of `fixers/`. The files a fixer runs on are filtered only by `fixerPaths` in `src/core/workflows/fixer-languages.ts` (the host pass `fixFiles`, `probeFixers`, `apply_fix`), so no fixer runs on a code file of a language it does not handle; a gate detector that adds a fixer program adds its `FIXER_LANGUAGES` row and a case in the gate-matrix block "fixer languages" (#2632).
