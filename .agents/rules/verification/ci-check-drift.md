Whether a CI workflow or README the run wrote runs a gate command its checks do not run as written is decided only by `ciCheckDrift` in `src/core/workflows/ci-check-drift.ts` (#2284), called at the checks stage of both workflow versions through `ciCheckDriftWouldStop` in `scheduler.ts`, and recorded through the `ci_check_drift` reason (shadow). A new file a run writes gate commands into (another CI system, a task runner) adds its reader to `fileGateCommands`; a new launcher (`npx`, `uv run`) goes into `WRAPPERS`, a tool whose subcommand names the gate into `SUBCOMMAND_TOOLS`, and an output-only flag into `BENIGN_FLAGS` or `BENIGN_VALUE_FLAGS`, each with a case in `tests/workflow-scenario-ci-check-drift.test.ts`, which fails when a toolchain's CI flag is not compared or a matching CI file records a drift. Both sides are compared through the scripts they run (#2416): a package-manager script runner joins `SCRIPT_RUNNERS` with the table it reads (`scriptTables`: `package.json`, `composer.json`, `deno.json`), and a runner whose targets the host cannot read (`make`, `just`, `rake`, `task`) joins `OPAQUE_RUNNERS`, which give no verdict without a check running the same command; each new row adds its case to the same test. A check's write form is read from its own `fix` (the record `detectGates` and `fixerCommand` already use), never from a second list of fixer flags, and a file list against globs through `coveredPaths`; a new formatter gate adds its write-form case to that test (#2567). An interpreter whose gate runs inline code (`pwsh -Command`, `Rscript -e`) joins `INLINE_CODE`, and one that runs a script file given first joins `SCRIPT_INTERPRETERS`, each with a case in the same test (#2593). A command's path word is dropped as covered only through `coveredPaths` (globs over the files a check lists) or `narrowerPaths` (a folder inside the check's broader path); a new form of a check's scope (another whole-tree word) goes there with a case in the #2634 block of that test (#2634).
