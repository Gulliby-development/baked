A test input built from a generated value where the request or a criterion asks for literal examples is read only through `GENERATED_VALUE_SHAPES` (`src/core/verification/generated-values.ts`, a `LanguageRecord` registered in `tests/language-parity.test.ts`, golden in each fixture's `generatedValues` over its `generated` file), on `maskNonCode` or `stripComments` text, and which kinds a request rules out only through `bannedGeneratedKinds` (#2344): a language added to `SUPPORTED_LANGUAGES` adds its row and a fixture sample with a literal twin and a commented copy, and a new spelling joins its row with a case in `tests/workflow-scenario-case-walk-generated-values.test.ts`. The case walk records what it finds (`generated` in the `case-walk/tasks/` record, path, line and kind, no code) and the `generated_case` stop reason, enforced since #2469 (the walk refuses through `generatedCaseRefusal` only when `refuseGenerated` is set from the policy's mode, so shadow keeps recording), replays in `replayCaseWalks`; a new refusal the walk adds takes its own context flag the same way, never reading the policy itself. What a test cannot write as a literal is told apart only by `RUNTIME_PATH_SOURCES` (same file, golden in each fixture's `runtimePaths` over its `generated` runtime file, which `generatedValues` never marks); a new exemption joins that record or its rule with a case in the same scenario test, never a filter at a call site.
