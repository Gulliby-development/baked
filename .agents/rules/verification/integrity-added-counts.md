A rule of the test-integrity guard that counts something "added" (a created file starts from nothing) reads the stated request through `specText`: the request with a person's accepted answers (`statedRequest`), the spec and the plan, built by `integrityRequirementText` in `scheduler.ts` for both scan scopes. A suppression that text names verbatim is prescribed (`prescribedSuppression` in `src/core/workflows/test-integrity.ts`), and a file whose suppression finding a person's spec conflict answer decided is not counted again (`settledSuppressions`). A new suppression spelling goes into `SUPPRESSION_SPELLINGS` (`src/core/workflows/quality/suppressions.ts`, a `LanguageRecord` registered in `tests/language-parity.test.ts`) under its language, in the same change as the linter gate that reads it, with an `example` line: the language's `suppressions` golden then records whether the integrity guard counts it, the `lint-suppression` rule reports it, a request naming it prescribes it and a string literal holding it does not count, so never add a spelling to the guard's or the rule's regular expression instead (#2274). For a stack's own linter it also gets its row in `PRESCRIBED_SUPPRESSION` for the gate-matrix cell "prescribed suppression is not added" (#2270). The other "added" counters (`test-hook`, `verification-bypass`) read the same `specText` only in shadow (`prescribedExemptions`, recorded as `shadowPrescribed`, #2277); making an exemption live is a pull request of its own after bench rounds.
