The edge-input probe of a planned source task (`edgeProbe` in `src/core/workflows/scheduler.ts`, `src/core/verification/edge-inputs.ts`) decides a case only through `edgeDecision`, records its inputs under `probes/edge/` (kind `edge-probe`, kept in bench traces) and replays in `replayEdgeProbes`. A runtime limit worth probing goes into the language's `NUMERIC_LIMITS` row (a language-bound record: its golden in `tests/fixtures/languages/*.json` changes with it), never into the profile's instructions. A new path that settles a planned task calls the probe as the serial and parallel implement paths do, and `tests/workflow-scenario-edge-probe.test.ts` covers it (#1808). A probed case that crashes (the edge probe's, a chain battery's, a sibling probe's, and a reviewer finding's inconclusive repro through `reproCrash`, #2152) is decided only through `edgeCrashDecision`, on the output tail its record keeps (`caseCrash`, `outputTail`), and records its would-be finding through the `edge_crash_finding` stop reason (shadow until promoted). A new runtime's frame spelling joins the frame table (`CRASH_FRAMES` in `edge-inputs.ts`) with a case in `tests/workflow-scenario-edge-crash.test.ts`, whose table test fails on a row without one (#2136). The review and convergence gates decide the crash rule only through `gateAllows` (`reviewGateCrashKeeps`, `convergenceGateCrashKeeps`), with a case in `tests/workflow-scenario-repro-crash.test.ts`. Output is read through `outputLines`, which reads a CI annotation (`::error …::`, line breaks escaped as `%0A`) as the lines it carries; macOS and Windows run all tests only in the merge queue (a pull request runs only the tests `scripts/pr-targeted-tests.ts` picks), so a decision on CI output gets a unit case with the long temp path and annotation of those runners (#2153).
