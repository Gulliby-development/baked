Whether a file a task delivered keeps the block the request gives for it verbatim is decided only by `suppliedDrifts` in `src/core/workflows/supplied-drift.ts` (#2332), from the host apply records (`host-apply/tasks/`) and `suppliedBlocks`, called at the checks stage of both workflow versions through `suppliedDriftWouldStop` in `scheduler.ts`, and recorded through the `supplied_drift` reason (shadow). Which writes it compares is `comparableWrite` alone, from the record's inputs; a new kind of verbatim block (`SuppliedBlock`) adds its comparison to `blockDrift` with a matching and a drifting case in `tests/workflow-scenario-supplied-drift.test.ts`. Content the host writes for a planned task from the plan rather than the request (a host-written task's `write.content`) is compared with the request's blocks before it is written, only by `planContentDrifts` (the same `suppliedDrifts`) through `suppliedPlanContent` in `scheduler.ts`, and under `hostApply: "on"` replaced only with `hostApplyContents` (#2472); a new path that writes plan or model text for a file the request supplies goes through it, with a case in `tests/workflow-scenario-host-apply-plan-content.test.ts`.
