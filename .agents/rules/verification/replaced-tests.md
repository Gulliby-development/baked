Whether the test-integrity guard exempts a test a review finding asks to change is decided on the diff and the finding's subject, not on the fix's verb (#2139): a removed test that a spec-basis finding on the file names in its claim and that the same change replaces with a test under a new title is replaced, not removed (`replacedTests` in `src/core/workflows/test-integrity.ts`, recorded as `replacedBy` finding ids in `integrity/decisions/`), on the one `integrityDecision` both workflow versions share. The removal regexes (`REMOVE_TEST`, `KEEP_TEST`, `TEST_REMOVAL_OBJECT`, `REMOVE_FILE_TESTS`) stay only for a removal with no replacement. A new wording or evidence rule of the guard adds a phrasing pair (one the rule matches, one it does not) to `tests/workflow-scenario-test-integrity-replaced.test.ts`, as #2032's rule requires, and a case for each language with a test title convention to its language table. A language's new test-framework row (`src/core/intelligence/test-frameworks.ts`) that names tests where the guard named none before ships with `shadow: true` (#2147): it is read only by `shadowTitleFindings`, which records what it would add or clear (`shadowTitles` in `integrity/decisions/`), and has an exempt and a flagged row in the shadow table of that test file; promoting it drops the flag and moves its rows to the live table. An exemption a correction's own finding grants is computed only by the `*Targets` functions of `test-integrity.ts` (`rewriteTargets`, `strengthenTargets`, `consolidateTargets`), which both scheduler call sites pass into `ScanOptions`; `consolidateTargets` (#2467) lets a spec finding that asks for literal rows merge tests into tables while the file keeps a test and nine tenths of its assertions. A new exemption adds its `*Targets` function there, both call sites, and a case per language to its scenario test, as `tests/workflow-scenario-integrity-consolidation.test.ts` does.
