Whether a fenced block the request attributes to a path is that file's content or a listing about it (signatures, an outline) is decided only in `suppliedBlocks` in `src/core/workflows/sizing.ts`: a block named by its first-line path comment, after prose whose clause about it does not say it is the whole file (a prose line that only names the path is no such evidence, #2666), is marked `listing`, and so is a block of declarations without bodies whatever its prose says (`declarationOnly`, #2666: TypeScript, Go, Rust, Java and Python stubs; a `.d.ts`, `.pyi` or C header, an interface, trait, extern block or protocol is content); a new language's bodiless declaration form or declaration-file kind goes into `declarationOnly`'s tables with a cell in the `declaration-only` matrix of `tests/gate-matrix.test.ts`; and every reader of supplied files (`hostApplyDecision`, `comparableWrite` and `suppliedDrifts`, `suppliedTestFiles`) skips a listing instead of taking the block as the file; a new reader of supplied file blocks honours `listing`, and a new header or prose form adds its case to `tests/workflow-scenario-host-apply-shadow.test.ts` and the per-language cell of `tests/gate-matrix.test.ts` (#2438). Which path a block is for is decided only by `blockPath` (with `headerPath` for the first-line comment) in the same file: a header path wins over the prose and a header naming a file outside the asked paths makes the block nobody's, and the host-apply readers (`hostAppliableTasks`, `hostApplyInputs`, `hostApplyContents`) ask with the one set `hostApplyPaths` gives, never their own; a new header syntax (a comment marker, a trailing-text form) adds its case to the #2453 tests of `tests/workflow-scenario-host-apply-shadow.test.ts` (#2453).
