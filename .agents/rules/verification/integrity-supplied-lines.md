A counter of content a run "added" (the test-integrity scan's suppressions, the shadow test-hook and verification-bypass exemptions in `src/core/workflows/test-integrity.ts`) reads the lines the request gives verbatim the way the quality gates do (#2489): through `suppliedLinesOnce` in `src/core/workflows/supplied-drift.ts`, passed in as `ScanOptions.suppliedLines` so the scan imports none of the request readers, and a match on such a line is the request's, bare or not, recorded apart (`suppliedSuppressions`) for the replay, never counted (#3059). Each supplied text is excused at most as often as the request writes it, so a session's second copy of the marker is still counted. A new counter of added content takes the same input, with a case in `tests/workflow-scenario-integrity-supplied-suppression.test.ts` and its negative (the marker on a line the request does not supply).
