Every refusal of acceptance (`acceptance()` in `src/core/verification/acceptance.ts`, the unreconciled-effects check after it, and `assertNoPendingDecisions`) is thrown through `acceptanceRefusal` with the advice its predicate takes from `src/core/verification/acceptance-advice.ts`: the object it refuses on (the finding, check, review, task, request or criterion ids) and the command that changes what the predicate reads (a fork from the stage that runs it again, the command that answers a decision, revise or cancel), never a model switch, since no model reads a host predicate. The scheduler marks such a stop under `refusals/acceptance/`, and `acceptanceRefused` keeps the invalid-output repeat guard (its note to the model and its `reroute` advice) away from it, so the advice after a second block is still the predicate's; `retryRefused` holds only for advice that offers `reroute`. A new predicate in `acceptance()` comes with its remedy and a row and case in `tests/workflow-scenario-acceptance-refusal-remedy.test.ts`, which fails on a refusal with no recovery (#2879).
