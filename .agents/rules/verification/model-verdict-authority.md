A host decision that takes a model's verdict as authority over a run's own evidence (an audit's `matches`, a reviewer's claim) stores that verdict with the evidence the host can re-check, and a verdict against what the code did is re-checked once before it settles anything, as the derivation re-audit of a spec conflict does (`reaudit` in `src/core/workflows/scheduler.ts`). Every conflict decision that overrules criteria records them as `criterionIds` through `recordConflictDecision`, so the case walk stops demanding their literals; `tests/workflow-scenario-reaudit-row-conflict.test.ts` and `tests/workflow-scenario-misquoted-row-conflict.test.ts` fail when either is skipped (#1788). A model's claim that the request states something is evidence the host can re-check: it carries the request's words (`quote` on a derivation) and the host checks them against the request before the claim settles a row (`checkedDerivations` in `src/core/workflows/derivation-audit.ts`, #1823); a new place where a model cites the request adds the same check. A conflict decision uses verified quotes, not report wording (#2016): whether the request settles a `spec_conflict` is decided by `requestConflictDecision` in `src/core/workflows/request-conflict.ts` on the sides the host checked against the spec and the request (`checkedSides`) and on the request re-audit's checked quotes, on every report of a task, and records its inputs under `conflicts/request/` for `replayRequestConflicts`. The request those quotes are checked against is the person's words, read only through `personRequest` in `src/core/workflows/person-request.ts` (#2492): for a feature of an initiative the original request section after `FEATURE_REQUEST_HEADING` with a person's accepted answers, never the host-composed framing of `featurePrompt` (the scope fence settled R80 ratdec core T014 for the request); every reader that takes the request as the person's authority over a run's own work (conflict sides, the re-audit's quotes, the documentation-example site) reads it there, a new one too. A new host-composed section of `featurePrompt` goes before that heading, with a case in the framing list of `tests/workflow-scenario-spec-conflict-request.test.ts` whose quote must not verify. A new rule of `specConflict` that reads the report goes through checked sides or a checked quote, never a phrasing regex like `namesRequestSide` (kept only as the first-report fallback), and adds its case to `tests/workflow-scenario-spec-conflict-request.test.ts`, whose first-report phrasings (request, brief, contract, task text) fail when the decision hangs on one word. The same holds for the other host decisions that settle for the request or the platform (#2032): an analysis inconsistency (`requestSettles`), a review amendment for the request (`specAmendmentOf`), a platform limit and a documentation example of `specConflict` decide through `evidenceDecision` in `src/core/workflows/evidence-decisions.ts` on a checked request quote or a quoted line of a failing check's or probe's recorded output, record their inputs under `conflicts/evidence/` for `replayEvidenceDecisions`, and keep their wording regex only as the fallback when no evidence is offered. A new rule that settles a finding or a conflict for the request or the platform adds an `EvidenceSite`, reads checked evidence, and adds a phrasing pair (one the regex matches, one it does not) and an unfound-quote case to `tests/workflow-scenario-checked-evidence.test.ts`. Whether the host corrects a misquoted test itself instead of opening a session (`misquoteFix`, #2047) is decided only by `misquoteFixDecision` in `src/core/workflows/misquote-fix.ts` on the sites `misquoteFixPlan` reads, recorded under `conflicts/misquote/` for `replayMisquoteFixes`; the edit is journaled and kept only when the task's required checks pass on it. A new spelling the plan rewrites (an escape layer, a raw or interpolated string) adds its case per language to `tests/workflow-scenario-misquote-host-fix.test.ts`, which fails when a second session opens after a fix whose checks pass. Whether the host finishes a task whose conflict it settled, instead of opening the settlement's session (`conflictFinish`, #2033), is decided only by `conflictFinishDecision` in `src/core/workflows/conflict-finish.ts` on the attempt's tree (edits, the case walk with the overruled criteria released, no overruled expected value left in its tests, intact row blocks, then the task's required checks), recorded under `conflicts/finish/` for `replayConflictFinishes`; a new settled-conflict branch that may finish on the host goes through `conflictFinish` in `src/core/workflows/scheduler.ts` and adds its case to `tests/workflow-scenario-spec-conflict-request.test.ts`, which fails when a second session opens after a settlement whose tree already passes.
