Whether the host would apply a task's content from the request's verbatim blocks instead of starting an implementer is decided only by `hostApplyDecision` in `src/core/workflows/host-apply.ts`, from the inputs `hostApplyInputs` records in `host-apply/tasks/<task>.json`; the blocks come only from `suppliedBlocks` in `src/core/workflows/sizing.ts` (the reader supplied-lines pricing also uses, on `fences()` and `changedLines`/`diffSections`). It skips the implementer only under the policy's `hostApply: "on"` (#2333), and there only when the task's `supplied-checks/` record has no conflict: that record is read for the decision only through `suppliedCheckVeto` in `src/core/workflows/supplied-checks.ts`, passed to `hostApplyRecord` as `suppliedConflict`, and no other site vetoes an apply; a new veto input joins `hostApplyVerdict` with its case in `tests/workflow-scenario-supplied-checks-shadow.test.ts` (#2462), where the content comes only from `hostApplyContents` and is written only through `writeHostFiles` (the journal with pre-images, as for a host-written task); any other path that applies request content on the host goes through one of those, never its own file writes. A new shape of verbatim content the reader takes (a fence form, a patch format, an apply command or flag) adds its case to `tests/workflow-scenario-host-apply-shadow.test.ts`, and a changed rule replays through `replayHostApply` (`newApplyDecisions`); that test fails when a case is not recorded or the hook does not catch an older rule (#2023). A fenced block next to a diff of the same file that quotes the change (its lines are the diff's, or its prose calls it the old or new line) is context, not a supplied file, decided only in `suppliedBlocks` (`quotesDiff`), never by a reader of its own; a new quoting form adds its case to `tests/workflow-scenario-host-apply-shadow.test.ts` (#2366). A Markdown section block is recognised only by `markdownRegion` in `sizing.ts` and placed only by `regionSections` and `applyRegion` in `host-apply.ts` (#2101); a new section form (another heading syntax, a file kind) adds its case to the region tests of that file. `git apply`'s arguments for the request's diffs are built in one place, `applyArgs` in `host-apply.ts` (with `patchForms` for the line-end forms tried and `baseDrift` for a zero-context diff's pre-image), used by the decision's check, `hostApplyContents` and the supplied-content checks of `supplied-checks.ts`; no other site spells out `git apply` flags, and a new diff shape (such as `-U0` hunks, #2412) adds its case to `tests/workflow-scenario-host-apply-shadow.test.ts` and, when the supplied-content check reads it, to `tests/workflow-scenario-supplied-checks-shadow.test.ts`.
