Which test targets the baseline replay runs on their own after a check does not build as a whole is decided only by `replayTargets` in `src/core/workflows/quality/baseline-replay.ts`, from the runner's `REPLAY_TARGETS` row (runs, or `none` with the reason the runner already builds each file or package on its own); a new test runner adds its row and its stack's cell to "baseline replay per test target" in `tests/gate-matrix.test.ts` (#2020). How the replay's first run keeps going past the first failing target is decided only by `replayCommand` in the same file, from the runner's `REPLAY_KEEP_GOING` row (the flag that keeps it going and the stop flags it removes, or `none` with the reason the runner already runs every target), read from the check's command before it runs; a new test runner adds its row, a case to `KEEP_GOING` in `tests/workflow-baseline-replay.test.ts`, which fails when a runner has no row, and its stack's cell to "baseline replay keeps going" in `tests/gate-matrix.test.ts` (#2364).
