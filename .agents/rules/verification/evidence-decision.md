Whether the host answers a spec conflict about a prescribed-row test file with the row diff is decided only by `evidenceDecision` at the `prescribed-rows` site on `conflictRowEvidence` (`src/core/workflows/conflict-row-reply.ts`, #2493), from `rowBlockDrifts` on the files the conflict names (`replyWithRows` in `scheduler.ts`, before every other settle of `specConflict`), never a second reader of row blocks or file rows; the reply's text comes only from `conflictRowDiff`. Each comparison records `conflicts/rows/<task>-<n>.json` and its decision `conflicts/evidence/prescribed-rows-<task>-<n>.json` (replayed by `replayEvidenceDecisions`); the host replies only with the policy field `conflictRowReply: "on"` (shadow otherwise). A new row notation needs nothing here (it is read through `rowBlockDrifts`), but a new place that settles a conflict about a test file (a corrective's conflict path, a best-of-N candidate) runs `replyWithRows` first and adds its case, per row notation, to `tests/workflow-scenario-conflict-row-reply.test.ts`, whose cases fail when the conflict is settled by a model instead.
