A row-file comparison that says a run added a row reads the file as it was before the run's first write of it, not the delivered file alone: `rowBlockDrifts` takes a `base` reader (`runBaseContent` in `src/core/workflows/rollback.ts` at the checks stage), `measureFileRows` marks a row the base held byte for byte (as often as it held it) `base`, and `rowMoveDecision` never counts such a row `added` nor pairs it with a missing prescribed row. A new caller that records added rows passes the same reader, and a new reader of `added` reads the record's `base` marks so the replay decides as the run did. R104 netfold `core` left the scaffold's placeholder rows of a second list for a later feature and was recorded as having added them (#2969); `tests/workflow-scenario-row-block-base-rows.test.ts` holds that case. Base rows are compared without their list separator, so a placeholder that becomes the last row of a list and loses its comma stays a base row (#2974); a new notation whose rows end in another separator adds it to that comparison and a case to the same test.
