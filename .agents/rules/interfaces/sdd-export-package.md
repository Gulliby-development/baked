The SDD export package (`baked workflow export-package`, [docs/workflows/sdd-export.md](../../../docs/workflows/sdd-export.md)) is built only by `buildSddPackage` in `src/core/workflows/sdd-export/package.ts`, which every surface calls. A change to what a run or an initiative persists (a new document of `specPublication`, a new initiative plan field, a new graph edge) updates the exporter in the same pull request, bumps `SDD_EXPORT_FORMAT_VERSION` when the layout changes, and updates `tests/workflow-sdd-export.test.ts`, which fails when a `specPublication` file is not exported; a version bump also updates the package importer and its test (#2206). The importer (`readSddPackage` and `importSddPackage` in `src/core/workflows/sdd-export/import.ts`) reads only what the exporter writes, refuses any other `formatVersion` and any file whose sha256 differs from the manifest, and seeds a run only through `StartRequest.seed` (`seedState` in `seed.ts`), which recomputes every hash and validates the package against the new workspace; an initiative keeps its seeds in the `initiative.imported` event, never in its settings, so the split digest stays that of the plan. A new exported document that a run needs to start updates `seedState` and `tests/workflow-sdd-import.test.ts`, which proves an imported feature analyzes without specifying or planning again (#2208).
