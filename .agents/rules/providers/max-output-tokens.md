A provider adapter bounds every model call at the call's `maxOutputTokens` (the agent profile's cap) and says how in `OUTPUT_LIMITS` (`src/core/llm/providers/output-limit.ts`): `request` when the AI SDK sends it, `{ env }` for the variable a CLI reads (Claude Code's `CLAUDE_CODE_MAX_OUTPUT_TOKENS`, set by `claudeCodeEnv`; a process kept across calls is keyed by the limit, as by effort), `{ stream: "why" }` when the provider takes no limit and the adapter guards its streamed output instead (Codex app-server), or `{ none: "why" }` when the provider offers neither. `tests/provider-output-limit.test.ts` fails on an adapter without an entry; no adapter drops the limit silently (#2547). A `stream` adapter counts each step's streamed text and reasoning with `streamOutputDecision` (past `STREAM_OUTPUT_FACTOR` times the limit), reads the `stream_output_limit` mode from `providerOptions.<provider>.outputGuard` (`withCodexOutputGuard` in agent-executor.ts), in `enforce` interrupts the call and ends the step `length` with what it streamed, and reports what it saw as `outputGuard` in the step's provider metadata, which the attempt's usage record keeps for `replayStreamOutputs` and from which the executor records the would-stop (`recordStreamOutputStops`); a new one adds its case to `tests/codex-stream-output-guard.test.ts` (#2660).
