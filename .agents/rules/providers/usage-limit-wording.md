Whether a provider error is an account refusal (a usage limit, spent credits, a rejected key, a missing CLI) is decided only by `accountRefusal` in `src/core/workflows/retry.ts`. A provider that gains a new usage-limit wording adds it to `USAGE_LIMIT` with a case in the limits table of `tests/workflow-provider-account.test.ts`, and every path that would otherwise retry, resume or record a lost worker (the call path, a parallel batch's worker outcome, the provider and owner-lost resumes) asks `accountRefusal` first, so a limit blocks the run as `provider_account` instead of spending resumes before its reset (#3055).
