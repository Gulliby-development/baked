A provider's usage-limit reset is resolved to a time only by `resolveUsageLimitReset` in `src/core/workflows/usage-limit-reset.ts`, from the words `usageLimitReset` keeps, in the zone the provider printed (no zone is the host's own). A provider whose CLI reports a limit as a structured event rather than in its error's words (Claude Code's `rate_limit_event` with `status: "rejected"`) appends that event to the failed turn's error (`rejectedNote` in `src/core/llm/providers/claude-code/session.ts`), so `accountRefusal` and `usageLimitReset` read it like any wording. A new reset wording adds a case to `tests/workflow-scenario-usage-limit-reset.test.ts`. Every path that blocks a run `provider_account` passes the reset to `noteUsageLimitResume`, which records the shadow `host-resume-on-usage-limit-reset` decision; a real resume timer is a pull request of its own after bench rounds show the would-resumes were right (#3056).
